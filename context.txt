🏪 Bondor Bati POS — Project Context & Architecture
=======================================================
Built with: Raw PHP (no frameworks), MySQL, Vanilla CSS/JS
Stack: LAMPP (Apache + MySQL + PHP), PWA-ready

🗄️ DATABASE SCHEMA
===================

1. Users & Auth
   - users: id, name, username, password, access_token (magic link, single-use), role (ADMIN/STAFF), is_active
   - staff_salaries: id, user_id, monthly_salary, daily_rate (generated: monthly/30), start_date, end_date
   - attendance_logs: id, user_id, absent_date, deduct_salary (1/0)
   - staff_permissions: id, user_id, page_slug (real-time access control)

2. Suppliers & Customer Dues
   - suppliers: id, name, contact, total_due
   - customer_dues: id, customer_name, phone, due_amount, log_date, shift, status (Unpaid/Paid)

3. Inventory & Daily Stock
   - items: id, item_name, selling_price, cost_price, min_threshold (stock alert)
   - raw_inventory: id, item_name, current_qty, avg_unit_price
   - daily_stocks: id, item_id, log_date, shift (Morning/Evening/Night), user_id,
                   carry_forward_qty, wastage_qty, complimentary_qty, fresh_processed_qty,
                   opening_qty, closing_qty, sold_qty, total_sales_amount
     UNIQUE: (item_id, log_date, shift)

4. Bazaar & Expenses
   - bazaar_ledgers: id, log_date, advance_cash, total_spent
   - bazaar_items: id, ledger_id, item_name, bought_qty, total_price, supplier_id
   - expenses: id, category (Gas/Fixed/Asset), name, total_amount, is_spread, daily_amount, remaining_balance, expense_date

5. Forecasting & Orders
   - calendar_events: id, event_date, event_name, impact_multiplier
   - advance_orders: id, delivery_date, customer_info, total_bill, advance_paid, status
   - advance_order_items: id, order_id, item_id, qty

⚙️ CORE BUSINESS LOGIC
========================

Logic 1 — Stock & Sales (3-Shift System)
  Opening Qty = (Carry Forward - Wastage) + Fresh Processed
  Sold Qty = Opening Qty - Closing Qty - Complimentary Qty
  Shifts: Morning → Evening → Night (carry-forward auto-loads previous shift's closing)

Logic 2 — Cash in Drawer
  Cash = (Total Sales - Due Sales) + Advance Received - Cash Bazaar - Cash Expenses

Logic 3 — True Net Profit
  Net Profit = Total Sales - (Bazaar Cost + Fixed Exp + Spread Gas + Prorated Salary + Wastage*CostPrice + Comp*CostPrice)
  Per-shift: Salary and fixed expenses prorated by ÷3

Logic 4 — Dues Separation
  Dues (Baki): Counted as revenue, NOT in cash drawer (unrealized profit)
  Complimentary: Not a sale, deducted at cost price as promotional loss

Logic 5 — Smart Gas Prediction
  next_gas_date = last_gas_date + avg_days_between_gas_purchases

Logic 6 — Bazaar Suggestions
  suggested_qty = avg_7day_sold * tomorrow_event_multiplier (1.0 if no event)

Logic 7 — Spread Expenses
  Each day's expense load = SUM of one-time expenses on that day + daily_amount of all active spread expenses

Logic 8 — Staff Access Control (Real-time)
  Permissions reloaded from DB on every page load (no caching in session for changes)
  Magic links are single-use (token nullified after first authentication)

Logic 9 — Custom Range Reports
  Date ranges: Daily / Monthly / Lifetime / Custom
  Metrics: Total Sales, Total Dues, Bazaar Cost, Spread Expenses (with overlap math), Salary Cost, Wastage Loss, Net Profit
  Analytics: Top 5 selling items, Top 5 high wastage items

Logic 10 — Low Stock Alerts
  If (latest closing_qty OR opening_qty) < items.min_threshold → show alert on dashboard + badge in Morning Prep view

🔐 AUTHENTICATION
=================
- Admin: session-based username/password (login.php)
- Staff: Magic link (?token=...) → session set → token nullified in DB (single-use)
- Staff login page accepts full URL or bare token
- Staff permissions are real-time (reloaded every request)

📱 OFFLINE SUPPORT
==================
- Service Worker caches CSS/JS/login
- JS offline queue: forms and actions stored in localStorage when offline
- Auto-sync fires on navigator.online event
- Visual amber banner shows pending queue count with "Sync Now" button

🌍 BILINGUAL SUPPORT
====================
- Toggle: ?action=toggle_lang (EN ↔ BN stored in $_SESSION['lang'])
- All views wrapped with __('...') helper
- Dictionary in core/Translate.php (120+ key-value pairs)
